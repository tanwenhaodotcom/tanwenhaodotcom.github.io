一个轻量、独立、长期可维护的 Hexo 主题

最近，我开始尝试自己开发一个 Hexo 主题，并将它命名为 Milo。

项目地址：github.com/tanwenhaodotcom/hexo-theme-milo

这并不是一个从零开始就有完整规划的项目。最初只是想解决自己使用 Hexo 主题时遇到的一些问题，但随着不断尝试，我逐渐意识到，与其一直寻找一个符合自己预期的主题，不如自己做一个。

于是，Milo 就这样开始了。

为什么要自己做一个主题？

在决定开发 Milo 之前，我一直在寻找一个设计简洁、阅读体验好，同时又足够轻量的 Hexo 主题。

我接触过不少优秀的博客，其中 Sukka 的博客给我留下了比较深刻的印象。

它的设计并不依赖复杂的视觉装饰，而是通过字体、间距、内容层级和细节交互，让整个网站看起来非常协调。

我逐渐发现，好的设计往往有一些共通之处。

它不一定需要特别复杂的布局，也不需要大量动画和装饰。真正重要的是信息如何组织、视觉层级如何建立，以及用户在浏览过程中是否感到自然。

不过，优秀主题的功能和设计并不意味着可以直接照搬。不同项目有不同的定位，我希望 Milo 最终能够形成自己的设计体系。

因此，我给 Milo 确定了一个比较明确的方向：

轻量、独立、长期可维护。

我不希望它成为一个不断堆砌功能的主题，也不希望为了实现某个视觉效果而引入大量依赖。

技术架构：尽量保持简单

Milo 基于 Hexo 开发，采用 EJS 模板、原生 CSS 和 JavaScript。

在技术选择上，我有几个基本原则：

  • 尽量使用原生 Web 技术。
  • 不为了简单功能引入大型前端框架。
  • 尽可能减少不必要的第三方依赖。
  • 将功能拆分为相对独立的模块。
  • 保持代码结构清晰，方便后续维护。

我认为，一个博客主题并不需要拥有多么复杂的技术栈。

它最重要的任务，是稳定地把文章呈现给读者。

因此，相比追求技术上的复杂程度，我更在意代码是否容易理解、功能是否可靠，以及未来是否容易继续修改。

设计与功能

Milo 目前已经具备一套比较完整的博客功能。

1. 简洁的双栏布局

桌面端采用双栏布局。

左侧是文章列表，右侧是博客信息，包括作者资料、最近文章和分类。

Milo 桌面端首页预览，左侧为文章列表，右侧为博客信息侧栏。

首页主要展示最新文章，文章标题、摘要、分类、发布时间等信息采用相对克制的排版。

移动端则采用响应式布局，导航调整为两行，文章内容根据屏幕宽度重新排列。

2. 阅读体验

文章详情页是我比较重视的部分。

目前已经实现：

  • 自动生成文章目录。
  • 移动端折叠式目录。
  • 阅读进度显示。
  • 代码块一键复制。
  • 图片懒加载。
  • 可选图片灯箱。
  • 相邻文章导航。

这些功能并不是为了让页面看起来更复杂，而是希望读者在阅读长文章时能够更方便地定位内容。

例如，阅读进度在桌面端采用悬浮组件，移动端则改成贴近屏幕底部的细进度条，尽量减少对正文的遮挡。

3. 搜索体验

搜索是博客中很容易被忽视，但实际使用频率不低的功能。

Milo 提供文章搜索，并在搜索结果中高亮匹配关键词。

目前支持中文、英文、多个关键词以及特殊字符场景。

搜索结果的长文本也针对连续英文字符串进行了换行处理，避免内容撑破页面布局。

4. SEO 与内容分发

主题还包含：

  • 页面 Title 和 Description。
  • Canonical。
  • Open Graph。
  • Twitter Card。
  • 默认分享图片。
  • Atom Feed 自动发现。

这些功能主要是为了让博客页面在搜索引擎、社交平台和订阅阅读器中能够正确呈现。

5. 404 页面与侧边栏交互

404 页面采用独立模板，保持与主题整体风格一致。

另外，桌面端还增加了粘性侧边栏。

当用户向下滚动时，作者资料卡正常离开视野，而最近文章和分类模块会吸附在浏览器顶部附近。

这一功能使用原生 CSS 的 position: sticky 实现，没有增加额外的 JavaScript 滚动监听。

我很喜欢这种设计：它不会明显增加页面复杂度，却能改善长页面的浏览体验。

开发过程：从能用到稳定

Milo 的开发并不是一次完成的。

整个过程经历了多轮迭代，每一轮都围绕实际使用中发现的问题展开。

最初处理的是基础模板、链接和导航问题，随后完善 SEO、文章阅读体验、图片加载和搜索功能。

再往后，工作重点逐渐转向细节：

  • 首页文章数量调整后出现的布局异常。
  • 404 页面重新设计。
  • 搜索结果关键词高亮。
  • 连续英文长字符串造成的横向溢出。
  • 移动端阅读进度组件的优化。
  • 归档页面展示策略。
  • 多级文章目录的交互。
  • 桌面端粘性侧边栏。

这些问题有些看起来很小，但真正使用一个主题时，体验往往就是由这些细节决定的。

为了减少修改带来的回归问题，我也逐渐为项目补充了自动化测试，并建立了独立的本地预览环境。

现在修改主题源码后，可以在本地实时查看页面效果，而不需要每次都重新部署正式博客。

目前已经完成多轮回归测试，并在 Chrome 和 Edge 中检查了桌面端、平板和不同尺寸的移动端布局。

Milo v0.2.0

2026 年 11 月，Milo 发布了第一个公开预发布版本：v0.2.0。

项目地址：

https://github.com/tanwenhaodotcom/hexo-theme-milo

版本发布：

https://github.com/tanwenhaodotcom/hexo-theme-milo/releases/tag/v0.2.0

目前项目已经具备比较完整的基础功能，但还不能说它已经达到最终稳定状态。

Safari、Firefox 和真实 iOS 设备仍然需要进一步测试，实际博客环境中的兼容性也需要继续验证。

接下来，我会优先处理稳定性、兼容性和安装体验，而不是急着增加更多功能。

最后

开发 Milo 的过程让我有一个比较深的感受：

一个博客主题真正困难的地方，并不是把某个功能做出来，而是让所有功能在不同页面、不同设备和不同使用场景下都能自然地工作。

有时候，为了修复一个很小的布局问题，需要检查模板结构、CSS 规则和 JavaScript 生成的 DOM；有时候，最好的优化反而是删掉不必要的代码。

我希望 Milo 最终能够成为一个不需要频繁折腾、可以长期使用的 Hexo 主题。

它不需要拥有最多的功能，也不需要追逐每一种新的设计趋势。

只要足够简洁、稳定、易于维护，就已经达到了我最初的目标。

Milo，仍在继续。
